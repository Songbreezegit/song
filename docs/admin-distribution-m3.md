# 内容分发 M3 发布日历与人工报告

开发基线为 `origin/main` 的 `e6e2f8ec481dbdc64fe5ae790aceaebab5523414`，与任务书一致。M3 在独立的 `feat/admin-distribution-m3` 工作树开发。

## 技术设计

- 发布任务按 UUID 独立记录。同一平台稿可排期多次。创建时核对账号、当前目标关系、就绪状态和平台稿版本，再在同一事务内冻结文案、账号资料、素材顺序、封面和处理说明。
- 任务、事件和素材引用使用独立表。源内容、平台稿、账号及已排期素材通过 `RESTRICT` 外键保留。显式采用新平台稿版本后，旧版素材引用继续保护审计历史。
- 客户端只读任务和历史。公开 Invoker RPC 通过私有状态转换函数完成写入。每次成功操作更新任务版本并追加事件，事务失败时整体回滚。同一操作者的相同请求重放原响应，旧版本或复用请求 ID 提交其他操作返回 `PT409`。
- 计划、待确认、人工报告、取消分别对应 `planned`、`awaiting_confirmation`、`manually_reported`、`cancelled`。退回计划及纠正报告需要理由。人工报告保存实际发布时间、操作者、账号、内容版本和链接或备注，证据标识为 `manual_user_report`。
- 新建和改期选择将来的时间，已经过期的任务可继续人工处理。改时区时按新时区解释输入的本地时间。重复时间显示两个 UTC 偏移供选择，跳过的本地时间需要重新选择。日历按所选 IANA 时区计算左闭右开的 UTC 查询范围。
- 发布日历提供月、周、列表视图，日期、时区和筛选保存在 URL。桌面按日期网格和当日任务分栏，手机以紧凑日期按钮和当日任务列表为主。任务详情使用独立路由，按操作打开一份表单，保留现有后台字体、间距和颜色变量。
- 导出沿用 M2 的人工准备格式，取任务绑定的快照并附上任务和计划时间。平台主页由用户点击打开。过期标签、浏览、复制和导出均通过只读数据生成。

## 使用与兼容性

从待发布的平台稿点击「安排发布」，或在日历选中日期后点击「安排此日」。任务详情可复制或导出冻结文案、查看素材、改期、取消以及明确采用新版平台稿。进入人工流程后，可用作品链接或确认备注回填实际发布时间。发布历史支持按计划时间、平台、账号和状态查找，详情时间线可展开原始事件。

历史列表按计划时间和任务 UUID 排序，查询每页 48 项。月和周的格子显示已加载的任务摘要，选中日期后查看该日任务。已归档账号可用于历史筛选。默认时区为 Asia/Shanghai，日历允许通过 URL 保存选择。

M1 的草稿删除在存在发布任务时会提示查看发布历史。原稿与平台稿编辑、字段同步及导出仍使用现有接口。M3 的素材引用保留到历史保留策略另行评审；取消或采用新版均保留曾被任务引用的旧素材。现有素材公开可访问性与 M1/M2 一致。

M4 可在独立表记录表现、推广归因及证据来源。若未来接入官方 API，可另行设计可信执行服务和核验状态，继续保留人工报告事件语义。

日历使用按需加载的 `temporal-polyfill` 1.0.8。2026-11-13 核对 npm 版本和 MIT 许可证，发布于 2026-11-04，npm 安装包解包约 1.02 MB。此依赖负责 IANA 时间转换和 DST 消歧，界面使用现有后台组件。[上游项目](https://github.com/fullcalendar/temporal-polyfill) · [Temporal 时区转换规范](https://tc39.es/proposal-temporal/docs/zoneddatetime.html)
